[SECTION 1] PROJECT KYA HAI? (Simple Real-Life Story)
--------------------------------------------------------------------------------
Scenario:
Ek person trip par gaya (jaise Goa ya Dubai). Wahan uski flight delay ho gayi
ya baggage gum ho gaya. Usne trip se pehle Travel Insurance le rakhi thi.

Pehle ka manual process:
- Physical bills aur forms courier karne padte the.
- Claim pass hone me 15-20 din lag jaate the.
- Koi tracking nahi thi ki claim kahan atka hua hai.

Hamara Solution (Automated Web System):
1. Customer Portal:
   Traveler online form bharta hai (Policy No, Flight No, Claim Amount, Reason).
2. Reviewer Dashboard:
   Insurance officer ke paas live dashboard par naya claim instantly aa jata hai.
3. One-Click Decision:
   Reviewer claim check karta hai aur ek click me "Approve" ya "Reject" karta hai
   (Reject karne par reason likhna mandatory hai).
4. Real-time Persistence:
   Saara data H2 database me instantly update aur save ho jata hai.

[SECTION 4] TOP 10 VIVA QUESTIONS (Crisp & Direct Answers)
================================================================================

Q1: CI aur CD me kya difference hai?
Ans: CI (Continuous Integration) me code continuously build aur test hota hai.
     CD (Continuous Deployment) me test pass hone ke baad code automatically
     production server par live deploy ho jata hai.

Q2: Direct main branch me commit kyun nahi karte?
Ans: Agar direct main me commit karein aur code me bug ho, toh live app crash ho
     sakti hai. Isliye feature branch par kaam karke testing ke baad Pull Request
     ke through code merge kiya jata hai.

Q3: Multi-Stage Dockerfile ka kya advantage hai?
Ans: Multi-stage build se Docker image ka size bohot chhota aur secure ho jata
     hai. Build tools (jaise Maven, JDK) sirf build stage me rehte hain, aur final
     image me sirf lightweight runtime (JRE) aur compiled JAR jaati hai.

Q4: Container ko root user se kyun nahi run karna chahiye?
Ans: Security privilege escalation se bachne ke liye. Agar container root se run
     hoga aur application me koi vulnerability aayi, toh attacker host system ka
     control le sakta hai. Non-root user system ko secure rakhta hai.

Q5: Selenium ko headless mode me kyun chalaya?
Ans: Do main reasons:
     1. Speed: Headless mode me UI render nahi hoti, isliye tests bohot fast run hote hain.
     2. CI/CD Environment: Jenkins servers me graphical display / monitor nahi hota,
        isliye background headless execution zaroori hota hai.

Q6: Ansible me Idempotency ka kya matlab hota hai?
Ans: Idempotency ka matlab hai ki ek playbook chahe 1 baar run ho ya 100 baar,
     system ka final state hamesha exact wahi rahega aur koi duplicate changes
     ya errors create nahi honge.

Q7: Database kahan run ho raha hai aur data kahan save hota hai?
Ans: Spring Boot ke andar embedded H2 In-Memory database use kiya hai. Application
     chalu rehne tak data memory me rehta hai. Testing aur viva demo ke liye yeh
     fast aur zero-configuration solution hai.

Q8: Automated Rollback kaise trigger hota hai?
Ans: Naye version ke deployment ke baad Ansible health check verify karta hai.
     Agar HTTP 200 OK nahi milta, toh rollback playbook automatically trigger
     hoti hai aur backup JAR ko active kar deti hai.

Q9: Git merge conflict kab generate hota hai?
Ans: Jab do alag-alag branches me do developers ek hi file ki exact same line ko
     differently modify kar dete hain, tab Git automatically merge nahi kar pata
     aur manual conflict resolution demand karta hai.

Q10: Jenkins Declarative Pipeline ka kya benefit hai?
Ans: Yeh ek structured aur readable format provide karta hai jisme stages
     (Checkout, Build, Test, Deploy) clearly separated blocks me hote hain. Isko
     Git me version control karna aur maintain karna easy hota hai.
