# Task 10 — Selenium Testing in Jenkins

## 1. Objective
The objective of this task is to integrate the automated Selenium End-to-End (E2E) tests into our existing Jenkins pipeline. We ensure that our pipeline runs the UI-based tests, handles dependencies (like browser and webdriver), fails the build if any test fails, and publishes the test results using the JUnit plugin.

## 2. Approach
- **Selenium Execution**: Our `SeleniumE2ETest.java` uses Selenium 4's Selenium Manager, which automatically detects the local browser (e.g. Chrome) and downloads the matching WebDriver version if one doesn't exist. Tests run in headless mode (`--headless=new`) to support running in a CI/CD environment without needing a GUI/display.
- **Jenkinsfile Changes**: We utilized the existing `Test` stage that runs `mvnw.cmd test`. Since the Selenium tests are standard JUnit 5 tests, Maven executes them automatically. 
- **Reporting**: We added a `post { always { ... } }` block to the `Test` stage using the `junit` pipeline step to publish the `.xml` reports generated by Surefire.

## 3. Pipeline Changes
The `Test` stage in `Jenkinsfile` was updated as follows:
```groovy
        stage('Test') {
            steps {
                bat 'call mvnw.cmd test'
            }
            post {
                always {
                    junit 'target/surefire-reports/*.xml'
                }
            }
        }
```
This ensures test results are captured and visualised on the Jenkins dashboard, regardless of whether the tests pass or fail.
